# 截图视觉审查与 e2e 修改意见（visual-review）

> 指导模型对前端页面截图做**像素级分析**、对照本规范设计语言给出**可执行的
> e2e 修改意见**的审查协议。本篇是规范中唯一以**运行页面截图证据**为验收面的
> 章节：声称视觉 / 像素结论时，以本篇协议产物为唯一合法证据。

## 用途与触发场景

- **触发**：截图像素级审查、视觉走查、设计还原比对、视觉回归复验、页面截图
  诊断、要求给出 e2e 修改意见的任务。中后台与公开页面任务均可叠加。
- **条件加载**：本篇为条件叠加工作面，不改变四个核心场景主分类；纯代码任务
  不读。命中时在常规场景判定（SKILL.md Workflow）之外额外读本篇。
- **用户直接贴截图**：同样按本篇协议审；缺采集工具面时走 §发现记录与 e2e
  修改意见格式 的 `observation` 分支：允许只读图、图内定位、未知字段与
  `needs-evidence` 结论，不因工具缺失而跳过读图或编造量测值。
- 修改意见落地产生的代码改动照常走质量门与三方体验账——视觉证据是新增
  证据面，不替代命令证据（[engineering](engineering.md#三方体验账)）。

## 证据采集协议

**截图矩阵**：视口 × 粒度 × 状态三维展开，逐格采证，禁止只截一张桌面首屏
就下全页结论。

| 维度 | 取值 |
| --- | --- |
| 视口 | 桌面 1440×900 / 平板 768×1024 / 手机 375×812（与目标仓库断点真源对照增删） |
| 粒度 | 视口首屏（第一印象与层级）/ fullPage 整页（节奏与密度）/ 元素级（局部问题定位） |
| 状态 | 默认态 + 交互态（hover / click 后 / focus-visible / disabled）；加载态与就绪态分开采 |

- **粒度互斥**：元素截图与 fullPage 分两次采，不在同一张图里混合诉求。
- **就绪判定（目标状态为主）**：等待目标选择器出现 / 目标元素可见；**网络空闲
  可选**（默认关闭）——对 SSE、WebSocket、长轮询页面显式豁免，不得以网络空闲
  作为默认门禁；固定超时兜底（默认 30s）**超时按失败**处理而非挂死。加载态
  用受控请求（拦截器固定响应）单独采集，不依赖等待。
- **动画冻结前置**：截图前冻结 CSS / JS / SVG 动画（注入动画暂停样式或固定
  时钟）；若冻结阻止状态推进（如 loading→ready），先截冻结前状态、再解冻到
  就绪后截，禁止用冻结把页面停在中间态。未冻结动画的截图不具比对资格。
- **字体与图片就绪**：截图前确认 `document.fonts.ready`、图片 `complete` 与
  连续两次 `requestAnimationFrame` 布局稳定；任一未满足按采集失败处理。
- **环境元数据必填**：视口、DPR、浏览器及版本、OS、渲染引擎、**字体环境**
  （容器镜像 digest 或字体包版本）、页面缩放、滚动位置、裁剪偏移与 frame path
  写入产物元数据；DPR 强制固定值并在元数据登记，DPR 不一致的截图作废——
  **复验必须同环境同参数比对**，换环境的对比无效。
- **截图产物治理**：截图产物**落盘**存证并记录 SHA-256，不内联进对话或日志；
  fullPage 截图设置高度上限（**8000px**），超限自动分段，分段各自记录元数据。
- **结构+坐标一次采集**：除截图外同时取语义快照（a11y 树）与元素边界盒
  （视口相对 CSS 像素坐标）。视觉观察由此落到可量测坐标。**坐标空间声明**：
  使用裸坐标时必须声明坐标空间（截图是否缩放 / 重采样），换算回原图并
  **回标**到截图上复核后才允许引用。
- **DPR 双采样**：CSS 像素口径保跨设备尺寸一致；设备像素口径出高清图查
  发丝线、图标模糊、亚像素错位。
- **动态区域排除**：时间戳、轮播、随机数据等不稳定区域以**掩码清单**
  声明式登记（selector 或像素矩形），比对前统一掩蔽；保布局的隐藏（占位仍在）
  与移除（占位消失）语义分开，按比对目的选用。
- **实例数先行**：审查列表 / 卡片网格时先数元素实例数；数量与预期不符直接
  记 finding，不做后续像素比对。内滚容器、虚拟列表与 iframe 需在覆盖范围中
  显式声明是否已采集；`fullPage` 不自动等于业务内容全量。

**工具面声明（宿主无关）**：完整执行需要宿主提供等价原语——三级截图、
带边界盒的语义快照、CSS 规则查询（胜出声明 / 被覆盖声明 / 源码行）、环境
仿真（暗色 / 强对比 / 减动效）、页内脚本量测。宿主不具备时降级为「用户提供
截图 + 代码侧量测脚本」或 `observation` 证据级别：读图照做，数值从样式源码
与量测脚本取，不虚构。

## 观察纪律

1. **先读截图再判断**：每张截图必须读回模型真正看图后才能下视觉结论；
   「从代码猜效果」是违规操作。未读图产出的视觉结论一律作废。
2. **定量走脚本、定性走截图**：对比度、触控目标、间距与字号的像素值用页内
   脚本量测（模型从图片读不出精确对比度）；截图只做层级、平衡、节奏、一致性
   的定性判断。两类结论分开陈述，不互相冒充。
3. **语义与视觉交叉验证**：a11y 树阅读顺序 vs 截图视觉顺序对照，抓 float /
   absolute 打乱逻辑流的问题；交互控件的名称、角色以语义快照为准复核。
4. **视觉 → CSS → 源码行回溯链**：截图发现问题 → 语义快照定位元素 → CSS 规则
   查询看胜出声明与被覆盖声明 → 修改意见落到具体规则与源码行。`observation`
   级别允许停在图内定位与 `needs-evidence`，升级到修复建议前必须补齐回溯链。
5. **环境矩阵**：暗色 / 强对比 / 减动效仿真下对关键页补一轮截图；
   `prefers-reduced-motion` 开启时位移 / 缩放动效应停（token 纪律见
   [design-tokens](design-tokens.md#动效与交互状态)）。
6. **主观结论门禁**：风格、品味、品牌契合类结论必须真实读过截图才允许输出；
   纯自动扫描（数值量测、静态检查）不得输出主观品味结论。禁止虚构截图、
   量测值与目标仓库的设计规范。

## 八维走查清单

按固定顺序走查八维，每维逐条核对。判定标准分三层，禁止混层：

1. **WCAG 标准底线**（不可用品牌 token 或项目偏好豁免）：正文对比度 ≥4.5:1、
   大字 ≥3:1（WCAG AA；大字指 ≥18pt 或 ≥14pt bold，约 24px / 18.67px）；目标尺寸
   ≥24×24 CSS px（WCAG 2.2 AA，含间距、行内、用户代理、必要等例外）。
2. **项目 token 约定**（跟随目标仓库真源）：间距刻度、字号阶梯、圆角、控件高度
   以 token 真源为准，缺省值只在真源缺位时兜底。
3. **审美建议**（不进入缺陷列表）：强调色数量、节奏变化、装饰取舍等只作建议区。

| 维度 | 走查项与审查缺省值 |
| --- | --- |
| 对齐 | 同列元素左右边线对齐；栅格一致；图标与文字基线对齐；高清采样下无亚像素错位 |
| 间距 | 间距优先落在 token 真源刻度（无真源时参考 8/16/24/32/48/64）；同层区块间距一致；区块节奏有疏密分组而非均匀堆叠 |
| 字阶 | 标题—正文—辅助三级层级差清晰；行高 1.4–1.7、长文行宽 50–75 字符为排版建议；字号取自 token 真源，不虚构「缺省字阶」；移动端正文 ≥14px 为建议下限 |
| 色彩 | 正文对比度 ≥4.5:1、大字 ≥3:1 为 WCAG AA 底线（量测取值，禁用态/logo 等例外按 WCAG）；语义色与 token 真源一致；强调色数量为审美建议 |
| 层级 | 首屏视觉动线先落主信息与主行动；页头槽位废黜、内容壳锁视口等骨架约束与 [general-pages](general-pages.md#布局骨架) 一致 |
| 密度 | 移动端无横向溢出；触控目标以 WCAG 2.2 AA 24×24 CSS px 为底线，44×44 / 48×48 为平台建议或增强级目标；卡片与表格密度匹配中后台任务节奏，不为「丰富」堆装饰 |
| 一致性 | 圆角 / 阴影 / 控件高度与 token 真源一致；图标风格与粗细统一；四态视觉承载与 [general-pages](general-pages.md#四态一致承载) 一致 |
| 可访问性 | focus ring 可见未被移除；交互四态齐备（[general-pages](general-pages.md#交互态与可访问基线)）；语义顺序 = 视觉顺序；图片 alt、控件名称在语义快照中可核 |

**AI 味黑名单核对**：以下手法本身合法，但「无论主题是什么都出现」即判
「默认值而非选择」，记入建议区并要求给出来自 brief 或真源的依据——
米色暖底 + 陶土色强调；近黑底 + 单一荧光强调；报纸式发丝线框 + 零圆角；
无视层级的统一圆角卡 + 同款灰影 + 渐变装饰块；每个标题上方全大写 eyebrow
标签、中点连接的元信息、假充黑的近黑色值、一律等宽的小数据标签、链接统一
箭头后缀；无语义依据的编号标记（内容并非序列时）。

**装饰自减法**：每页只允许一个视觉锚点，其余保持克制；定稿前执行「删掉一件
配饰」检查——找出一个不服务主题的装饰并给出去除建议。标语 / 说明文字 / 次要
标签类问题不在本篇重新裁决，直接走 [界面删减](general-pages.md#界面删减) 的
删除试读与保留清单。

## 偏差判定

**发现准入四门**：只把以下四类录入正式 finding 列表——功能错误；可验证的
无障碍问题；实际布局破损（溢出、遮挡、错位、裁切）；违反项目已采用的设计
约定（本规范条文、目标仓库 token 真源与 AGENTS 约定）。纯审美偏好与「潜在
优化」降级为建议区，不进缺陷列表、不进入一键修改。「未录入」不得表述为
「全站无问题」。

**像素级比对语义**（设计还原比对与复验场景适用）：

- **感知色差而非 RGB 差**：逐像素用亮度 + 色度加权的感知色差判定，阈值语义
  默认 0.1（1 = 黑白之差）；RGB 欧氏距离会把人眼不可见的差异放大成假阳性。
- **双阈值并报**：差异像素占比与「尺寸锁定」分别报告；元素尺寸变化即使像素
  差异很小也单独记 finding。**尺寸不一致默认判失败**并输出期望 vs 实际尺寸；
  业务允许尺寸漂移须显式声明并记录原因。
- **动态区域掩码清单化**：动态内容以「**掩码清单**」声明式登记（selector 或
  像素矩形），比对前统一掩蔽；掩码清单随变更评审，不临时口头豁免；掩码本身
  必须保留原图与掩码范围记录。
- **透明资产保留 alpha**：比对输入保留**原始 RGBA**；透明像素用棋盘格 / 多
  背景合成比较，**不得统一压到单一固定背景**；同一 RGB 但 alpha 不同视为差异，
  避免透明 logo、渐变遮罩被漏检。
- **抗锯齿豁免**：文字与边缘的 1px 级渲染微差按抗锯齿规则降级为非问题
  （邻域同时存在更暗更亮像素、且明暗邻居在两图均有成片同色支撑才豁免；
  成片等色块上的差异不豁免）。故意审查文字渲染质量时关闭豁免。
- **聚簇（聚集度）只排序**：散点噪声与真实回归的聚簇度只用于**排序、定位与复核候选**，
  **不得自动排除**差异；关键文本、状态点、交互区域必须逐项复核（少量像素
  可能改变业务含义）。
- **差异方向编码**：比对结论写明变亮 / 变暗 / 位移方向，不只报「有差异」。
- **结构性 diff 优先**：先给出插入 / 移动 / 尺寸变化等结构结论，再下钻像素级
  差异；结构未明时不逐像素罗列。

**还原度分层验收**：不设「像素级一致」硬门槛——按结构 / 内容 / 交互状态优先于
间距 / 字号等视觉细节做**分层验收**；允许有依据的折中，折中记录原因；折中不得
触碰 WCAG 标准底线。

## 发现记录与 e2e 修改意见格式

**三级证据级别**（先声明级别，再产出对应产物）：

| 级别 | 允许的输入 | 可交付结论 |
| --- | --- | --- |
| `observation` | 仅截图 / 读图，无 DOM、无源码、无环境元数据 | 可交付观察报告；finding 标 `needs-evidence`；允许图内定位与未知字段；不得声称已修复或已复验 |
| `runtime-confirmed` | 截图 + 语义快照 / 计算样式 / 量测 | 可下缺陷判定与修复建议；修复值须来自 token 真源 |
| `fix-reverified` | 前后同参数截图 + diff + 回归核对 | 可声明修复闭环；基线推进仅此级别允许 |

每条 finding 强制字段按级别裁剪，缺必需项即未完成的审查产物：

```text
finding:
  category: <功能错误 | 无障碍 | 布局破损 | 违反设计约定>
  level: <observation | runtime-confirmed | fix-reverified>
  observed: <区块 + 元素定位（selector/uid + 坐标或图内位置）+ 量测值或读图观察>
  expected: <阈值 / token 真源值 / 规范条文依据；observation 可写待补>
  rule_ref: <本规范文档#章节 或 目标仓库约定条目>
  fix:
    intent: <意图层：该做什么，一句话>
    locate: <定位层：token 真源项 / CSS 规则与源码行 / 组件形态 / 删减动作 / role+name 修复；observation 可写待补>
    value: <修改值，必须来自 token 真源或规范缺省值，注明出处；observation 可写待补>
  reproduce: <采集环境与状态，供复验同参数重截>
  verify: <复验方式：同参数重截 + 比对结论 / 量测脚本断言>
```

- **禁模糊表述**：反例「排版差」「间距不舒服」；正例「按钮量测高度 28px，低于
  组件 token `controlHeight=36`，建议改回 36px（design-tokens 组件 token）」。
  无坐标、无量测值、无规则依据的 finding 一律回炉——`observation` 级别例外，
  允许以图内位置 + 待补字段交付，但必须标 `needs-evidence`。
- **修复值必须来自真源**：动手前先扫目标仓库 token / CSS 变量 / 主题真源，
  修改值从既有 token 取并改真源、带 why 注释（[design-tokens](design-tokens.md#真源跟随规则)）；
  目标仓库未采用的字体 / 颜色 / 密度偏好不得作为修改理由。
- **形态级改动回设计推理**：finding 若要求变更页面形态 / 布局模式 / 组件组成，
  修改意见必须先回到 [design-reasoning](design-reasoning.md) 的设计产物流程，
  不在审查报告里直接发明新形态。
- **批量与排序**：finding 按 严重度（功能 > 布局破损 > 无障碍 > 设计约定）与
  用户动线位置排序；同根因合并（一个 token 偏差引发的多处 finding 合并为一条，
  列出全部命中坐标）。
- 修改意见落地即代码改动：照常过质量门与三方体验账，公开契约（路由 path /
  queryKeys / 权限键 / 接口形状）不因视觉修复变动。
- **协议违规单列**：审查产物自身的解析失败、空候选、输出与动作不一致等单列
  「**协议违规**」记录，不混同页面 finding，也不计为任务失败；重复出现时先修
  采集 / 解析链路再审页面。

## 修复复验闭环

1. **应用修复** → 按 finding 的 locate 与 value 改真源 / 规则 / 组件。
2. **同参数同环境重截**：视口、DPR、状态、等待条件与采集时一致；环境元数据
   不一致的对比作废。
3. **前后对比**：差异像素占比 + 方向 + 结构结论三联产出；「前后画面不同 ≠
   改善」——须排除误报（原 finding 是否成立）、说明收益与代价后才算闭环。
4. **回归核对**：修复点之外的区域不得出现新差异；新差异按 §偏差判定 重新
   走准入与记录。
5. **基线纪律**：比对基线不可原地覆盖；复验通过（finding 消除且无回归）才
   推进新基线，并保留前后证据。多轮迭代时同协议复跑，一轮到不了完美属正常，
   不得以「已修改」代替复验证据。
6. **重试两级协议**：
   - **采集稳定性重试**：截图采集阶段连续两次截图 SHA-256 一致才进入比对；
     默认可重试 **N=2** 次；仍不稳定记 `needs-evidence`，不进入比对。
   - **判定重试**：首次出现差异后同环境重复采集 2 次；全部一致差异 → `fail`；
     全部无差异 → `pass`；**混合结果 → `flaky`（`needs-evidence`）**，不得用于
     「无回归」结论或推进基线。重试记录（次数与各次差异量）写入报告。
7. **复验裁判一致性**：自动评审只消费**同一观察空间**（同一张截图 + 同一份
   元素表）；坐标式输出先映射回元素再判定；固定评审 prompt 与采样参数，保留
   运行日志供人工复核。

## 反模式

1. **从代码猜效果**——未读截图就下视觉结论；读图是审查的准入门禁。
2. **模糊表述**——finding 无坐标、无量测值、无规则依据，修改意见不可执行
   （`observation` 待补例外）。
3. **发明 token 值**——修复值不来自真源或规范缺省值，借审查开第二套体系。
4. **纯偏好进缺陷列表**——把审美倾向当缺陷，为显得工作量大而改动合理设计。
5. **前后画面不同当改善**——未排除误报、未说明收益代价即宣布闭环。
6. **把「未录入」说成「无问题」**——审查覆盖率之外的状态不得外推。
7. **裸坐标引用元素**——不给 selector/uid 与语义定位，坐标随布局漂移即失效。
8. **噪声级差异当回归**——散点渲染噪声不区分，制造假阳性淹没真实问题；反向
   地，把聚簇当自动排除依据会漏掉稀疏但真实的差异。
9. **公开页审美规则套进中后台**——hero、主 CTA、营销字阶被反向套进 CRUD 截图
   审查；两轨各按各的真源（SKILL.md 反模式同条）。

## 审查证据包

审查产物统一为 `visual-review.json`（`schema_version: 1`），字段：

```json
{
  "schema_version": 1,
  "review_id": "<稳定标识>",
  "mode": "review | verify",
  "level": "observation | runtime-confirmed | fix-reverified",
  "target": {"url": "<页面或文件>", "commit": "<目标提交>"},
  "environment": {
    "viewport": "1440x900", "dpr": 1, "browser": "<名称+版本>",
    "os": "<系统>", "font_env": "<镜像/字体包版本>", "engine": "<渲染引擎>"
  },
  "screenshots": [
    {"path": "evidence/step-01.png", "sha256": "<64 hex>", "format": "png",
     "step": "default", "state": "ready", "viewport": "1440x900",
     "scroll": "0,0", "crop": "0,0,1440,900", "frame": "main"}
  ],
  "findings": [
    {"id": "F1", "category": "布局破损", "level": "runtime-confirmed",
     "observed": "<定位+量测>", "expected": "<阈值/token>", "rule_ref": "<文档#节>",
     "status": "open | fixed | accepted | needs-evidence"}
  ],
  "masks": [{"selector": "<选择器或像素矩形>", "reason": "<为何动态>"}],
  "baselines": {"id": "<基线标识>", "hash": "<哈希>", "scope": "<视口/页面/状态>"},
  "coverage": {"viewports": [], "states": [], "pages": [], "not_covered": []},
  "retries": {"attempts": [{"result": "pass | fail", "diff_pixels": 0}],
              "classification": "pass | fail | flaky"},
  "verdict": "pass | fail | flaky | needs-evidence | not-run"
}
```

- `verdict=pass` 仅当 `retries.classification=pass` 且无未关闭 finding；
  `flaky` 不得推进基线；`not-run` 仅用于未执行。
- 截图路径必须相对证据包、存在且 SHA-256 匹配；禁止绝对路径与 `..`。
- 记录由 `scripts/visual_review_check.py` 校验（退出码 0/1/2）。

## 基线回归机制

**基线生命周期**：基线是**判定通过态的固化**，不是历史截图仓库。**建立**只在
`fix-reverified` 判定通过（`verdict=pass` 且 `retries.classification=pass`）后
执行，把当轮截图连同 manifest 逐图登记入库；**推进**只有判定通过的复采才
允许，且必须在 spec 包记录（来源包、比对结论、前后证据）后落库——`flaky` /
`fail` / `needs-evidence` 一律禁止。基线**不可原地覆盖、禁止自动更新**（与
§修复复验闭环 的基线纪律同一条款）：比对失败先按 §偏差判定 归因（掩码缺失 /
环境漂移 / 真实回归），不得改基线迁就现状。

**基线位置**：`docs/visual-baselines/<version>/` + `manifest.json`
（schema_version、version、source_pack、viewport、逐图
file/route/theme/locale/sha256）；版本号只增不改，新版本建立后旧版本只读
留存。

**比对语义**：引用 §偏差判定 的像素级比对语义——**尺寸不一致默认判失败**并
输出期望 vs 实际尺寸；透明资产保留 alpha（同 RGB 异 alpha 判差异）；差异
像素占比阈值默认 **0.1%**（占比 > 阈值判失败），调整阈值须随变更记录理由；
掩码清单在比对前统一掩蔽。实现真源为 `scripts/visual_baseline_check.py`
（仅标准库 PNG 解码，比对政策复用 `visual_review_check.alpha_aware_equal`）。

**工具即真源**：回归结论以工具退出码与报告为准——退出码 0 全部通过 / 1 有
失败或缺失 / 2 用法、IO 或格式错误；`--json` 逐图给出差异像素数、占比与差异
坐标样本。人工不复述、不改写工具结论；基线 manifest 自证用
`--manifest <path> --validate-only`（校验结构与逐图 sha256 与磁盘一致）。

## 响应式基线结构断言

响应式截图基线属于上节的基线生命周期：建立与推进仍以 `fix-reverified` 判定 /
判定通过的复采为前提，旧版本只读留存，不自动更新、不原地覆盖。响应式层把
[layout-system](layout-system.md#响应式规则) 的断点契约变成截图可回归的结构面。

- **基线位置**：`docs/visual-baselines/r<N>/` + `manifest.json` + `visual-review.json`；
  `version` 以 `r` 开头，旧版本只读留存。证据包按 §审查证据包 记录 before/after
  两次独立复采、`verdict=pass`、`retries.classification=pass` 与修复后的窄屏就绪
  判据，满足上节「建立只在 fix-reverified 判定通过后」的硬条件。
- **逐图字段**：manifest 逐图除 `file/route/theme/locale/sha256` 外必须带
  `breakpoint`（`xl` / `lg` / `md` / `sm`）与 `viewport`（`<宽>x<高>`）。文件名
  形态 `<route>-<breakpoint>.png`，每个覆盖路由四档齐备且不重复；证据包截图由
  `scripts/visual_review_check.py` 校验路径、哈希、重试与 verdict。
- **采集面**：`template/e2e/visual.spec.ts` 以 `VISUAL_RESPONSIVE=1` 开启响应式
  采集；桌面 8 格与响应式格分开开关，避免默认全量 e2e 时长翻倍。窄屏就绪判定
  只要求目标组件挂载与表头存在，表格首列可被横向滚动遮蔽，不以「首列可见」
  误判页面未就绪。
- **结构断言**：`breakpoint` 必须属于四档；`viewport` 必须与 PNG 实际尺寸一致
  （尺寸不符、字段缺失、断点未知均视为基线结构错误）；`environment` 与逐图
  sha256 仍按上节校验。实现真源同为 `scripts/visual_baseline_check.py`。
- **工具即真源**：常驻自证命令
  `python3 scripts/visual_baseline_check.py --manifest docs/visual-baselines/r1/manifest.json --validate-only`；
  回归比对命令 `--baseline docs/visual-baselines/r1 --capture <复采目录>`。
  人工不复述工具结论；`RESULT: pass` 与退出码 0 才算响应式基线通过。
- **门禁接线**：`scripts/gate.sh` 第 6 门与 CI python job 同源执行该自证命令；
  `scripts/tests/test_responsive_baseline.py` 锁定路由 × 断点矩阵、PNG 尺寸、
  自证 / 自比对与采集开关。真实采集复采证据见 `docs/visual-baselines/r1/CAPTURE.md`。

## 验证边界声明

本篇以运行页面截图证据为验收面：审查产物 = 证据包（含环境元数据与三级
level）+ finding 记录 + 复验对比（同参数前后证据）。量测值必须来自页内脚本
或样式源码，不从图片目测精确数值；未覆盖的视口 / 状态 / 环境不声称已审。
`observation` 可交付但不得冒充运行时确认或修复完成。除本篇协议产物外，规范
其余章节的验证边界不变——仍不以文档存在代替运行证据，不做 skill 效能实测。
