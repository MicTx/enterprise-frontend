# 测试设计指南（testing-guide）

> 按交付物类型回答「**测什么、怎么断言、边界在哪**」。编写或评审测试时读本篇；
> 测试纪律（怎么跑、串行受限内存、setup 位置）在
> [engineering](engineering.md#质量纪律)。

## 用途与触发场景

SKILL.md 路由表「测试编写与用例设计」场景读本篇。典型触发：新页面四步接线的
第 4 步（补权限与测试）、组件/纯逻辑交付、真源文件修改、缺陷修复的回归锁定、
规范审查中的测试形态评审。

## 测试设计四问（写用例前先回答）

1. **测什么行为**——用户可见的行为或对外契约，不是实现细节；
2. **断言什么可见结果**——渲染输出、返回值、调用的协作方（断言协作而非内部）；
3. **边界在哪**——零值、空集合、超长输入、转义字符、权限分支、失败路径；
4. **用什么形态**——按下表选形态，一个交付物可组合多形态。

## 测试形态与用例设计

| 交付物 | 测什么 | 断言方式 |
| --- | --- | --- |
| 纯逻辑（从页面/组件抽离的函数） | 边界值矩阵：零、空、超长、转义字符、非法输入 | 直接断言返回值（无渲染） |
| 真源一致性 | 清单 ↔ 消费方同步：放行清单 ↔ 路由、导航视图 ↔ 路由、样式契约 ↔ 样式源 | 引入**真实**真源配置断言，不用夹具替代 |
| 交互渲染（页面/组件） | 渲染冒烟（默认态）、主交互路径、权限分支、四态触发 | Testing Library `render`/`screen`/`fireEvent`/`waitFor`，断言用户可见输出 |
| 请求层 / SSE | 双通道契约、401 收敛、流解析 | `jest.mock` 框架面 + 构造流/响应夹具 |
| 样式契约（跨文件 CSS 合同） | 契约类/断点/滚动归属仍在源中 | 读源文件断言字符串结构（不渲染） |

用例设计规则：

- **每个数据驱动区块至少覆盖四态触发路径**（加载 / 空 / 错误 / 禁用——与
  [general-pages](general-pages.md#四态一致承载) 的四态一一对应）。
- **缺陷修复必须先落失败用例再修**（回归锁定）；修复注释引用用例名。
- **纯逻辑优先抽离**：页面内可测的转换/格式化/校验函数抽到独立模块做纯函数
  单测，不做「为测而渲染」。

## Mock 模式

- **框架面就近 mock**：`jest.mock('@umijs/max', …)` 写在测试文件内，按需提供
  `useModel`/`request`/`history` 等被用到的面——不建全局万能 mock。
- **不 mock 被测对象本身**；只 mock 协作方（框架面、网络、时钟）。
- **全局初始化集中在 setup 文件**（如 jest-dom）；逐文件差异进各自测试文件。
- **React Query 用内存 QueryClient 承载**（app 运行时已提供 Provider），请求层
  被 mock 后组件渲染不触网。

## 场景化清单

| 场景 | 该测什么 |
| --- | --- |
| 非地图 CRUD 新页 | 渲染冒烟 + 主交互（查/建/改/删路径）+ 四态触发 + 抽离纯函数的边界矩阵 + 接线一致性（路由 ↔ 导航） |
| 地图工作台 | 宿主 API 调用契约（不渲染地图即可断言）、预算/降级决策函数、告警与图例组件、资产引用（B6 由 ban_scan 承担） |
| 存量页面修改 | 触碰面回归：修改处行为 + 关联真源一致性断言 + 四态不回归 |
| 规范审查 | 测试形态评审：同名同目录、有断言（非空快照）、四态覆盖、mock 未覆盖被测对象 |

## 反模式

1. **只测成功态**——四态承载有规范要求，测试同责（违反与禁令同级）。
2. **断言实现细节**（内部 state、私有函数调用序列）——重构即碎，锁定行为而非结构。
3. **无断言快照**——快照必须配合显式断言或人工复核标记。
4. **mock 被测对象**——mock 后的测试不证明任何行为。
5. **测试里重写一遍被测逻辑**来算期望值——期望值应是独立给出的常量。

形态分类为规范约定；覆盖率数值、测试有效性、缺陷检出率为运行时指标，不在
本篇验证范围；本规范不以文档存在代替运行证据。
