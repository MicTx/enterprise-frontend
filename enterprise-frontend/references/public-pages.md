# 公开页面规范（public-pages）

> 企业自有前端中的公开访客页面：落地页、营销页、活动页、定价/对比页、公开门户
> 首页。条件加载：仅在任务命中公开页面时读；不改变四个中后台核心场景的判定，
> 也不把营销规则默认套进管理端。

## 用途与触发场景

- 条件叠加：落地页、营销页、活动页、定价/对比页按条件加载，不改变四个中后台核心
  场景的判定。
- 触发：新建或改造面向公开访客、以单一转化为目标的页面——试用/预约/下载/报名/
  购买/等待名单。页面首要任务是让访客完成一个主行动，而不是完成日常管理任务。
- 不触发：管理端列表/表单/详情、内部工作台、地图工作台；这些走非地图 CRUD 与地图
  章节，不读本篇。
- 与中后台的边界：公开页面允许并要求价值主张、证据、异议处理与主 CTA 等转化内容；
  这些是转化内容，不是 [general-pages](general-pages.md#界面删减) 所说的赘字。
  装饰性口号、空泛形容、重复说明与无信息标签仍按删减规则删除。

## 页面策略

### 单一转化目标

- 一页一 offer、一受众、一主行动；首屏只放一个主 CTA，不放竞争性 CTA。
- 转化定义必须是可观察动作（提交表单、开始试用、预约演示、下载、报名），不是
  「了解品牌」。
- 业务信息不完整时，按最接近收入/激活的动作做一行假设并继续，不因信息缺口停摆。

### 输入清单（只问缺失项，一次问齐）

- 目的：主行动、offer、转化定义。
- 受众：ICP、要解决的问题、前三项不转化原因、流量来源、访客落地时已知什么。
- 证据：客户 logo、证言、数据、案例、截图/演示、保障/退款/取消条款。
- 约束：品牌语气、视觉方向、移动优先、合规要求。

### 页面结构

- 首屏（必需）：标题（结果 + 受众）、副标题（怎么做 + 具体性）、主 CTA、一个证据
  信号、主视觉。
- 中段（论证）：问题→方案、3–5 个结果导向收益、三步如何工作、社会证明或案例。
- 底部（异议处理）：FAQ 6–12 问、风险反转（试用/随时取消/保障）、与首屏一致的
  最终 CTA。
- 结构可按流量意图裁剪；裁剪后仍须有「主张—证据—行动」闭环。
- 逐节构建：hero → benefits → how → proof → FAQ → final CTA；每次只改一节，保持
  diff 可审，不整页重写。
- 大字号强调段是可选表达，不是模板仪式；只有当它承载新的真实主张、且移动端可读性
  与性能都成立时才使用。

### 布局选择（选一种并说明理由）

| 类型 | 适用 |
| --- | --- |
| 经典首屏 + 分节 | 产品可由首屏截图/主视觉理解，最常见 |
| 长文叙事 | 需要教育市场、克服高怀疑 |
| 极简转化 | 高意图流量、下载/预约/等待名单 |
| 对比页 | 搜索意图含替代品比较，通常与 SEO 页配对 |

### 转化文案

- 标题公式（按语义改写，不机械套）：「{结果} without {痛点}」「{品类} for {受众}」
  「{时间} 内交付 {结果}」。
- 副标题 1–2 句：说明是什么、给谁、怎么做到。
- CTA = 动词 + 得到什么；不用「了解更多/提交」。
- 收益条目 = 加粗结果 + 证据/细节；先讲收益，再讲功能。
- 证据放在被支持的主张旁边；异议作为独立区块，不塞脚注。
- 具体化：用真实数字、客户名、场景；避免「提升效率」「全面赋能」这类空词。
- 流量来源与首屏承诺一致（广告词、搜索词、邮件主题）。
- 文案仍受界面删减约束：只保留承担转化、证据、异议、风险反转的内容。

## 内容真实性

公开页按 [general-pages §内容真实性](general-pages.md#内容真实性) 的基线执行，并追加：

- 生产证据必须真实：客户 logo、证言、指标、合规资质只用可核验来源；缺失写
  「待补证据」，不编造证明链。
- 示例/演示数据必须明确标注为示例，不把虚构客户、证言或业绩伪装成真实证据。
- 同一页数字口径一致（时间范围、币种、单位），避免可疑整数堆砌。
- 没有证据的价值主张降级为能力描述，不写成结果承诺。

## 视觉方向

- 公开页面的视觉方向可以比中后台更表达品牌，但必须收敛到**单一视觉真源**：目标仓库
  的品牌/主题 token（颜色、字体、字号、间距、圆角、阴影、动效）。没有真源时先建一套
  并记录理由，不按组件散落硬编码。
- 不引入第二套字体/图标/颜色体系；不把外部 skill 的字体白名单、色板、间距表、圆角表
  当作本规范常量。视觉方向是项目决策，不是通用禁令。
- 字体、字号、间距、圆角优先落在目标仓库既有阶梯上；需要新档位时改真源并写 why 注释。
- 单一字体家族；等宽仅用于代码/数据；目标品牌系统明确要求组合时从其规则。标题/正文
  在支持时用 `text-wrap: balance` / `pretty`，避免孤字。
- 嵌套圆角可用「内圆角 = 外圆角 − 间距」推导；结果 ≤2 时保持直角或沿用目标规则。
- 卡片边框四周完整或不用；背景保持平面，除非品牌真源明确要求。
- 首屏标题/副标题设可读行宽（约 45–75 字符，按目标字体实测），在语义断点换行。
- 移动优先检查：首屏 CTA 可见、标题不溢出、点击目标不小于目标仓库最小尺寸。

## 交互态与动效

- 四态与交互态基线见 [general-pages §交互态与可访问基线](general-pages.md#交互态与可访问基线)。
- 动效机制（只动画 `transform` / `opacity`、`prefers-reduced-motion`、
  `IntersectionObserver`、禁止未节流 scroll）唯一真源见
  [design-tokens §动效与交互状态](design-tokens.md#动效与交互状态)。
- 公开页追加：揭示一次、不回放；逐词/逐段强调是可选表达，不是必选项，性能或可读性
  不成立就退回静态排版；导航/移动菜单开关图标连续过渡，移动菜单用全高面板并管理
  焦点，链接入场错峰总时长设上限（目标组件体系优先）。

## SEO 与上线清单

- 索引决策：常青 offer、搜索意图匹配的公开页 → index；广告专用/时效活动 → noindex
  或非索引路径。索引页补 title、meta description、canonical、OG 图与内链。
- FAQ 用真实问题与答案；需要时加 FAQ 结构化数据，但不得标记不存在的内容。
- 上线清单：隐私/条款链接、品牌 404、表单校验、skip link、favicon、语义 HTML
  （nav/main/article/aside/section）、图片 alt、每页有返回路径。
- Cookie/同意提示按司法辖区要求；需要时不得省略。
- 404、表单校验、favicon、meta、alt 属于交付物，不是上线后补丁。


## 验证边界声明

本篇是结构、文案与视觉交付约束；转化率、视觉观感、动效流畅度是运行时结果，必须用
目标仓库运行页面或浏览器证据判断。没有运行证据时只声明静态结构通过，不声明「视觉/
转化已验证」；本规范不以文档存在代替运行证据。
