# 通用页面规范（general-pages）

> 非地图通用中后台页面规范：布局骨架、CRUD 模式、四态承载、路由弹层终层规则、
> 菜单与路由接线。SKILL.md 路由表「任何页面 / 组件 / 布局工作」默认首读本篇。

## 用途与触发场景

新建页面、扩展既有页面、存量页面修改、页面级一致性审查——进入任何页面/组件/布局
工作前先读本篇，写任何标语、说明文字、标签前先过 [界面删减](#界面删减)，触碰
表单 / 弹层 / 删除 / 提交路径先过 [操作反馈与用户控制](#操作反馈与用户控制)；
请求与数据面读
[data-layer](data-layer.md)，样式 token 读 [design-tokens](design-tokens.md)，
质量门、接线质量钩子与每次改动的三方体验账读 [engineering](engineering.md)，
地图场景另读地图章节；公开访客页面（落地页/营销页/活动页）另读
[public-pages](public-pages.md)，中后台任务不读；状态转换与动效决策另读
[state-transitions](state-transitions.md)（条件加载）。

## 布局骨架

- **Layout 分区先行**：业务页面内容区必须先按 [layout-system](layout-system.md#布局公理layout--cell--card--content)
  声明 Layout（rows × cols / areas），每个区域一个 Cell、每个 Cell 一个 Card、Card
  content 放内容组件；PageShell 只提供视口壳，不承担分区。裸 div 栅格、Card 套
  Card、一 Cell 多卡均为结构违规。
- **页头槽位废黜**：页面容器 ghost 模式 + `pageHeaderRender={false}` 常开；页面定位
  由菜单当前项与标签页标题承载，页内不再渲染大标题页头。全站默认，非逐页选择。
- **内容壳锁定视口**：页面级滚动不存在；滚动归属 Card body / 表格体
  （卡内滚 + `scroll={{y}}`）。内容壳占满内容区高度。
- **页滚例外必须显式声明**：确需页面级滚动的页面（长表单 / 内容流 / 调试流）传
  `exception` 类别字符串（如 `'long-form' | 'content-flow' | 'debug-stream'`），
  壳回到文档流；未声明的页滚视为违规，审查时直接判定。
- **高度链**：布局 header 高 56（`heightLayoutHeader: 56`），全屏内容页以
  `calc(100dvh - 56px)` 与之对齐；模块目录卡体等嵌套预算按同类 calc 链下探
  （如 `calc(100dvh - 190px)`）。不手写与高度链无关的零散高度值。
- **剩余高度填充**：内容区剩余高度用 `useFillRemainingHeight` 类钩子填充，不手写
  零散高度 hack。
- **模块页骨架 = 样式契约**：模块页目录/卡片骨架是全局样式的样式类契约
  （`.module-catalog-*` 类），不是组件文件；由「样式契约测试」守卫——测试直接读
  样式源断言 CSS 合同。该模式本身入规范：跨文件样式契约必须有同目录读源测试。
- **配套骨架件**：模块统计行、列表批量操作条为通用骨架件，新模块页复用不重造。

## CRUD 模式

中后台内容用 PageShell → PageLayout → PageCell → PageCard → 内容组件组织；Card /
ProTable / Modal+Form / Descriptions / Empty / Alert 的选型遵循 layout-system 与
下列 CRUD 惯例（目标仓库已有惯例时以其实际形态为准）：

- **列表页 = ProTable（卡内滚）**：ProTable 承载表格列表，滚动归属表格体。
- **编辑/创建页 = Modal + Form**：表单在路由弹层或页内 Modal 中以 antd Form 承载
  （ProForm 为组件面可用项；选型跟随目标仓库既有惯例，不虚构组件使用）。
- **详情页 = Descriptions（+ Drawer 承载）**：只读详情用 Descriptions 分区呈现，
  抽屉/弹层承载。
- **空态与警示**：列表/详情的空态用 Empty、运营警示用 Alert，不自制空态插画体系。

## 四态一致承载

每个数据驱动区块必须有加载 / 空 / 错误 / 禁用四态的一致承载方案，**禁「只有成功态」**：

- **加载态**：Skeleton 骨架族统一承载，不用自旋图标堆砌。
- **空态**：Empty 承载（见 CRUD 节）。
- **错误态**：ErrorBoundary 兜底 + 请求层统一错误处理（错误提示收敛到请求层统一
  入口，页面不自行 toast 轰炸）；401 收敛规则见 [data-layer](data-layer.md)。
- **禁用态**：控件 disabled 视觉由主题 token 承载（防浮层透底的 token 级案例见
  [design-tokens](design-tokens.md)），不在页面写一次性禁用样式。
- **审查口径**：页面审查时逐数据区块核对四态；缺任一态即规范违反，与禁令同级
  硬执行。

## 交互态与可访问基线

四态解决数据区块承载；可交互控件另需完整交互态，缺一即视为触碰面未完成：

- **交互四态**：hover / active / focus-visible / disabled 齐备；focus ring 不得以
  `outline: none` 移除。
- **键盘可达**：Tab 顺序跟随阅读顺序；模态/Drawer 焦点困在内部并在关闭后归还；
  长页面提供 skip link。
- **链接无死链**：`href="#"` 必须是禁用态或真实目标；当前导航项用 `aria-current`
  或等价标记。
- **语义与名称**：nav/main/section 等 landmark；图标按钮有 `aria-label`；表单控件
  有 label；图片有 alt（装饰图 `alt=""`）。
- **动效**：遵循 [design-tokens](design-tokens.md#动效与交互状态)；
  `prefers-reduced-motion` 下移除位移/缩放。
- **审查口径**：以上只作用于本次新增或触碰的界面，不借机整页补齐存量。

## 操作反馈与用户控制

复杂度留给系统：用户提交一个意图，系统负责确认生效、可收回、回来还在。
本节八条是**可判定规则**（每条可用页面状态 / 请求次数 / 焦点位置断言），
作用于本次新增或触碰的表单 / 弹层 / 删除 / 提交路径，不借机整页补齐存量。
状态转换的反馈形态（要不要动效、给哪格）见
[state-transitions](state-transitions.md)（条件加载）。

1. **默认值收敛**：表单、筛选、分页先给能直接用的默认值；不让用户填系统
   可推定的字段（当前页、默认页大小、当前角色可选项）。
2. **按需显示**：次级信息不进首屏；展开/详情/编辑的入口在，但内容不在
   初始渲染里占位。判断口径 = 初始可见区的信息能支撑当前任务闭环。
3. **即时反馈**：每个可触发的操作让用户立即可知「收没收到」——提交置
   confirmLoading / disabled 防连点，动作完成就地更新或给成功信号；
   慢请求期间显示进行态，不让界面看起来像没反应。
4. **撤回与可逆**：可逆操作给撤销路径；不可逆操作（删除、提交不可回退的
   变更）写明对象与后果后默认停在安全动作。不承诺接口做不到的撤销——
   删除成功后不可恢复的，不做「撤销删除」假按钮。
5. **误关保留输入**：表单弹层 / 抽屉的关闭分两态——未做任何修改直接关；
   有修改时默认动作是「继续编辑」，只有明确选择「放弃更改」才丢弃；
   取消按钮不发请求。草稿不写持久存储（业务草稿与密码不出会话内存）。
   「有修改」按实际字段值：onValuesChange 将当前值与打开时的基线比较（可空字段先归一）；改回原值后直接关闭，不用 sticky dirty 或 isFieldsTouched。
   表单本体可直接读 `form.getFieldsValue()` 与当前基线比较；保持同一份表单挂载，勿在确认前清空。初始焦点给「继续编辑」，不能仅用按钮颜色暗示。
   仅弃稿可用 context-aware `modal.confirm`（`App.useApp()`）：取消为「继续编辑」、确定为「放弃」。
   用 `focusable: { autoFocusButton: 'cancel' }` 给安全初焦；键盘实测，不能靠按钮颜色或文案。
6. **防误操作**：会发写请求的高风险确认（如删除）用受控 Modal，写明操作对象与后果，
   初始焦点落在安全动作（取消），危险动作标 `danger`；不由 static `Modal.confirm` 代管。
   提交期间锁住确认、取消和关闭路径，连按只生效一次。
   等待回包时保留上下文，不把在途写入显示为可撤销。
   失败时在弹层就地提示，原行不移除并保留重试；成功才更新并关闭。
7. **状态保留**：从详情 / 编辑返回列表，检索词、筛选、分页、滚动位置
   与选中行保持；慢翻页 / 刷新失败时旧数据继续展示并可重试，不打断
   检索、不跳回第一页、不让旧响应覆盖新请求的弹层。
8. **双语一致与名称不藏**：中英两版按钮与提示表达同一动作同一后果，
   动词语义对齐；主要操作、错误信息与可访问名称（aria-label / 纯图标
   按钮名称）不得藏进 Tooltip / 折叠区——那是把成本转嫁给读屏与
   Agent（[engineering](engineering.md#三方体验账) §不转嫁）。

## 界面删减

- **删除对象**：标语和口号式副标题；复述标题、控件或字段名已表达之意的说明文字；
  「欢迎使用」「在此处管理……」类引导句；只为「看起来丰富」的装饰性次要标签
  （不携带状态、数量、分类的 Tag / Badge）。
- **删除试读**：先假设这段文字不存在，只看布局：标题、分组、字段顺序、控件形态、
  空态能否让人读懂。读得懂就删。读不懂则**不补文字，重新设计布局**：调整分组与层级、
  字段顺序、控件形态、默认值，直到无字也读得懂；文字补丁不算修复。
- **作用域**：只作用于本次新增或触碰的界面；存量页面不借机整页清洗，与 SKILL.md
  Decision Rules 的最小完整变更一致。
- **自查钩子**（候选清单，不判违规）：
  `grep -rn -e "<Tag" -e "<Badge" -e "subTitle=" -e "tooltip=" -e "description=" -e 'type="secondary"' <目标>`，
  逐处做一遍删除试读；保留的要说得出落在保留清单哪一条。
- **与设计推理衔接**：新页面在 [design-reasoning](design-reasoning.md) 第 4 步产出
  「删减检验」，实现后对照。
- **公开页面例外**：公开页面的价值主张、证据、异议处理、主 CTA、FAQ 属转化内容，
  不按赘字删除；装饰性口号、重复说明、无信息标签仍删（细则见
  [public-pages](public-pages.md#页面策略)）。

**保留清单**（删减到此为止，越过即退化）：

- 四态文案：空态 Empty 描述、错误提示与重试、加载占位。
- 表单校验信息、必填标记，以及不可逆或高风险操作的确认说明。
- 单位、量纲、时区等限定词。
- 承载状态、数量、权限差异的 Tag / Badge。
- 控件的可访问名称：aria-label、纯图标按钮的名称兜底。被删的是可见赘字，不是名称，
  否则读屏用户与 AI Agent 的 role + name 定位一并失效。
- 其他规范条文已要求的用户可见提示：地图超预算降级提示、图例与告警，路由弹层「已是最终页」提示。
- 目标仓库明文要求的合规声明与业务术语。

## 内容真实性

- 不交付 lorem ipsum、「标题写这里」、TODO 占位；没有真实文案时写一版可审草稿。
- 示例数据要可信且标注为示例；不把虚构客户、证言、指标或资质伪装成真实证据，
  缺失时写「待补证据」。
- 系统消息具体：确认说清对象与动作，错误说清原因与下一步；不用感叹号和卖萌语气。
- 数字口径一致（时间范围、币种、单位），避免可疑整数堆砌。
- 禁用空泛填充词（示例而非穷举）：revolutionize / supercharge / cutting edge /
  effortless / world class；中文对应「颠覆/赋能/一站式/极致/无缝/引领未来」等，
  用可验证结果替代。

## Route modal 终层规则

- **弹层是导航终层**：路由弹层内再导航在弹层内终结（提示已是最终页），不用
  iframe / postMessage 跨层通信，不替换父级 pathname。
- **不静默替换**：`openRouteModal` 对已打开的弹层内容不做静默替换。
- **放行清单与路由真源同步**：路由弹层走放行清单机制（`ALLOWED_ROUTE_PREFIXES` 类），
  清单必须与路由真源保持同步，并有一致性测试守卫；漏配新路由 = 静默失败。
- **实现边界**：弹层内部用 MemoryRouter 渲染是允许的实现模式；页面路由/导航禁用
  第三方路由库的禁令语义见 [engineering](engineering.md) B2（命名导出黑名单）。

## 菜单与路由接线

- **双真源分离**：路由真源维护 path/component/access；导航视图真源只控菜单可见性
  （分组、白名单裁剪）。两处同步修改，不在菜单配置里写路由、不在路由里写菜单态。
- **隐藏菜单 ≠ 删除深链**：菜单裁剪只是可见性控制，深链仍可达，授权在后端——
  前端不以前端裁剪替代后端授权。
- **导航视图按角色白名单裁剪分组**：导航分组按角色白名单裁剪（模式级；具体分组
  与角色清单属各仓库真源，不做通用移植）。
- **权限真源**：页面权限键集中声明于权限真源（如 canAdmin 类能力函数），页面以
  access 钩子消费，不散落硬编码角色判断。
- **新页面四步接线**：建组件 → 路由真源 → 导航真源 → 权限 + 测试；步骤验收物与
  质量钩子见 [engineering](engineering.md) §新页面四步接线流程。

## 验证边界声明

本篇约束以静态约束检查与质量命令为验收面；CRUD 组件选型为模式级惯例，
不代表运行时视觉核验。布局高度链、四态视觉表现、弹层交互的最终效果以目标仓库
运行页面为准；本规范不以文档存在代替视觉证据。
